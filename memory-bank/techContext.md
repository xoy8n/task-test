# 💻 기술 컨텍스트 (Tech Context)

## 1. 기술 스택 (Technology Stack)

### 1.1. 프론트엔드 (Frontend)

- **언어/프레임워크**: React 또는 순수 HTML, CSS, JavaScript
  - 이유: 사용자 인터페이스(UI) 개발의 편의성과 컴포넌트 기반 아키텍처를 고려하여 React를 우선적으로 고려합니다. 간단한 구현의 경우 순수 HTML/JS로도 충분할 수 있습니다.

### 1.2. 백엔드 (Backend)

- **언어/프레임워크**: Node.js (선택 사항)
  - 이유: 프론트엔드와 동일하게 JavaScript 생태계를 활용하여 개발 효율성을 높일 수 있습니다. 만약 게임 로직 전체가 클라이언트 사이드에서 실행되거나, 외부 API(예: 단어 사전 API, AI 응답 API)만을 사용하는 경우 백엔드가 필요 없을 수도 있습니다.

### 1.3. AI 단어 추천 (AI Word Recommendation)

- **방식**: 내장 단어 데이터베이스(DB) 또는 외부 API (예: ChatGPT API)
  - 내장 DB: 초기 구현이 간단하고 빠르지만, 다양한 단어 생성 및 문맥 파악에 한계가 있을 수 있습니다.
  - 외부 API: 더 자연스럽고 다양한 단어 생성이 가능하지만, API 호출 비용 및 응답 속도 지연을 고려해야 합니다.

## 2. 데이터 관리 (Data Management)

- **한글 단어 리스트**: JSON 파일 형태 또는 간단한 DB (예: SQLite)에 저장하여 관리합니다.
  - 이유: 게임의 핵심 데이터로, 쉽게 접근하고 업데이트할 수 있어야 합니다. 초기에는 JSON 파일로 시작하여 필요에 따라 DB로 확장할 수 있습니다.
- **사용된 단어 기록**: 각 게임 세션별로 사용된 단어 목록을 관리합니다.
  - 구현: 프론트엔드에서는 JavaScript 배열/Set으로, 백엔드가 있다면 세션 저장소나 인메모리 DB를 활용할 수 있습니다.
  - 이유: 중복 단어 입력을 방지하고 게임 규칙을 적용하기 위해 필요합니다.

## 3. 개발 환경 (Development Setup)

- **버전 관리**: Git & GitHub
- **패키지 매니저**: npm 또는 yarn (프론트엔드 및 Node.js 백엔드 사용 시)
- **코드 에디터**: VSCode 또는 사용자 선호 에디터

## 4. 기술적 제약 조건 (Technical Constraints)

- **브라우저 호환성**: 주요 최신 웹 브라우저(Chrome, Firefox, Safari, Edge)에서 원활하게 동작해야 합니다.
- **응답 속도**: 사용자의 단어 입력 후 AI의 응답까지 지연 시간을 최소화하여 쾌적한 게임 경험을 제공해야 합니다. 외부 API 사용 시 이 부분을 특히 고려해야 합니다.

## 5. 의존성 (Dependencies)

- (프론트엔드 React 선택 시) `react`, `react-dom`
- (백엔드 Node.js 선택 시) `express` (API 서버 구축 시)
- (테스트 라이브러리) `Jest`, `React Testing Library` (선택 사항)
- (단어 사전 API 또는 AI API) 관련 SDK 또는 HTTP 클라이언트 라이브러리
